## Method

1. **Schools**: the 16 degree-granting schools on IU Bloomington's schools page, named as it names them (`data/iu_schools/schools.json`).
2. **Programs**: IU's degree finder data for Bloomington, the list behind "Browse All Programs". Each row names the program, its degree and its school(s). Rows that share a URL are one program.
3. **CIP codes**: IU publishes no program-to-CIP list without an IU login (its Academic Program Inventory is behind IU single sign-on, and the state's is behind a CHE login; checked again 2026-11-12, along with Kelley's STEM-designation pages, which name no codes). So each program gets its code from a reviewed rule in `data/iu_schools/program_cip_rules.json`, and the build accepts a code only if IU Bloomington (UNITID 151351) reports it in IPEDS Completions 2023-24 at the program's own award level, apart from the `title-match` majors below. Rule kinds:
   - `title`: the CIP title names the same subject (History -> 54.0101 History, General).
   - `degree`: IU reports the whole degree under one code, so a major in it takes that code unless it has a `title-match` rule. For example, IPEDS shows 2,407 Kelley business bachelor's awards under 52.0101 Business/Commerce, General and no major-specific business code at bachelor's level.
   - `title-match`: a major of such a degree whose name is, exactly or nearly, the title of a CIP 2020 code (CIP 2020 to SOC 2018 crosswalk titles; NCES definitions in `data/iu_schools/raw/CIPCode2020.csv`) takes that code instead (Kelley BSB Marketing -> 52.1401 Marketing/Marketing Management, General). IU's own guide to reporting by CIP code says its IPEDS codes "may classify some academic programs using a more general rather than a specific CIP code", so this code is not in IPEDS; the build checks the degree's general code (`ipedsCip`) against IPEDS instead. A major named "A and B" takes the codes of the parts that have one. Every such major has its own rule and note, and a major with no such title keeps its degree's code in its own rule (`degree`), so every major of these degrees is reviewed one by one.
   - `reviewed`: matched by subject where the title differs; the rule's note gives the reason (usually "the only code in this subject IU Bloomington reports at this level").
   - `double-major`: a program named "A/B" takes the codes of A and B.
   - `none`: left unmatched on purpose, with the reason. Nothing is guessed; a new program with no rule stops the build.
   - A rule with `campusUnitid` is the one exception to "IU Bloomington reports it": for a school whose degrees IU reports under another campus, the code is checked against that campus's IPEDS rows instead. Every such program is listed under "Codes confirmed at another IU campus".
4. **Jobs**: the NCES CIP 2020 to SOC 2018 crosswalk (sheet CIP-SOC) gives each code its SOC occupations, then each SOC is matched to the app's 830 jobs.
5. **Kelley roles**: the Kelley School also always includes the 50 Kelley roles (their 47 SOC codes, `src/utils/kelleySocs.ts`), basis `kelley-roles`, so the school filter never leaves out a job the original Kelley filter shows.

### SOC roll-up

The app uses BLS OEWS codes. 818 of its 830 are SOC 2018 detailed codes and match directly. The other 12 are combined codes (12 with listed parts), BLS broad groups (for example 13-1020 Buyers and Purchasing Agents) or OEWS aggregates (for example 21-1018). The crosswalk only uses detailed codes, so a detailed code the app holds inside one of these counts as that job.
