# Agent notes

## Cursor Cloud specific instructions

- **App:** Vite + React SPA (`npm run dev`). No database/Docker. Claude calls go through `/api/claude/messages` (Vite proxy in dev; `api/claude.ts` on Vercel).
- **Package manager:** npm (`legacy-peer-deps=true` in `.npmrc`). Install with `npm install`.
- **Tests:** `npx vitest run` (no `npm test` script). Lint: `npm run lint` (some pre-existing purity/unused-var failures exist outside recent feature work).
- **Claude model caveat:** `claude-sonnet-5` rejects `temperature` — do not send it (see `src/utils/claude.ts`).
- **OOH vintage:** Growth rates are BLS Employment Projections / OOH **2024–2034** (`DATA_SOURCES.BLS_OOH`, `scripts/extract_bls_data.py`).
- **OES vintage — national and state-level extracts are independent and CAN drift apart, so check each one's own source, not this note:**
  - National per-role employment (`src/data.ts`, drives terrain height + the Workers stat + the "OES" badge) is **BLS OEWS May 2025**.
  - State-level employment/LQ (`src/data/geo_real.json`, drives the 2D map) is also **BLS OEWS May 2025** as of the last refresh — but check `geo_real.json`'s own `_meta.bls_release`, don't assume it still matches `DATA_SOURCES.BLS_OES`; the two are refreshed by the same script but at different times.
  - Both are refreshed via `node scripts/refresh_oes_data.mjs`, which pulls `api.bls.gov` directly — `www.bls.gov`/`download.bls.gov` 403 all automated clients, so the classic workbook route can no longer be refreshed programmatically. Requires a free BLS key (`VITE_BLS_API_KEY`; unregistered tier is 25 req/day, nowhere near enough for the ~5,000-series state pass). Rewrites `DATA_SOURCES.BLS_OES` + all 50 `dataSources` literals in `data.ts` together — `src/__tests__/oesVintage.test.ts` guards them staying in sync.
  - `MAP_TITLE_TO_SOC` (`src/utils/onet.ts`) is the single source of truth for both extracts. BLS retired SOC 13-1022/13-1023 (Wholesale & Retail Buyer / Purchasing Agent) and now publishes only the combined broad code **13-1020** — both titles map there as aliases.
- **All-occupations dataset:** `src/data/occupations/` (`index.json` + one `<SOC major>.json` per BLS major group) is built by `python3 scripts/build_occupations.py` from OEWS May 2025, EP 2025–35 Table 1.2 (`data/bls_ep_occupation_2025_35.xlsx`, Wayback capture) and O*NET 30.1; `scripts/verify_occupations.py` re-reads every value from the raw files, including the EP "Summary" rows stored for every continent and minor group. Only `src/utils/occupationIndex.ts` may import it: `index.json` is bundled, continent files load lazily via `import.meta.glob` (`occupations.test.ts` and audit T68 guard both). Display labels live in `src/config/continents.ts`; the BLS title in the data is the official name.
- **22-continent world (phase 2):** the 3D view is `components/world/` (instanced peaks, one draw call per region; region rectangles in the ground shader). In the code, `mapView: 'globe'` is this 3D landscape view, not a globe. Region area = the continent's EP 2025 summary row (`utils/worldLayout.ts`, `continents.test.ts`); position/shape are layout only. `utils/roles.ts` adapts the 50 Kelley jobs + 830 BLS occupations into one list (a Kelley SOC is never listed twice). Unscored occupations open `OccupationPanel` via `worldStore.selectedOccupationSoc`, never `selectedJob`, so they never reach the auto-analyze Claude call (`unscoredNoClaude.test.tsx`).
- **Three levels:** the 3D view is at the world, a family or a field, held as `focusedFamily` + `focusedContinent` in `worldStore` (a field's family always comes from `familyOf`). All transitions, what is on stage, the breadcrumb, the Esc and zoom-out rules and every click rule are pure functions in `utils/worldLevel.ts`, so change them there. Any new level state must also be added to Landscape's wake effect, or fades freeze partway (`landscapePause.test.ts`).
- **Stages:** a family or field is drawn as the live 3D view, not as part of the treemap. `CameraRig` lands every one on `stageFraming` (the live camera, identical numbers for all 27); on phones only it also slides the picture with `camera.setViewOffset` (`stageViewOffset`) so the disc's centre sits in the middle of the free band, measured from the chrome during the flight. That offset goes through the projection matrix, so labels, pins and raycasts need no special handling, and it eases back to none at the world. Reset view hides on phones inside a family or field (`utils/resetView.ts`). `world/StageTerrain` draws one surface: the live Terrain.tsx shader in `world/stageShaders.ts`, displaced from baked textures instead of a 50-entry uniform loop, so 8 jobs and 378 go down one path. `utils/stageLayout.ts` places jobs with the live disc layout (`territoryLayout` in `terrainMath.ts`): a field's territories are its SOC minor groups, a family's are its fields, spacing and hill width scale with the job count. `utils/stageBake.ts` bakes two height layers (2025 and 2035) on one fixed scale per stage, `stageMaxEmployment`, the largest employment on the path, the same rule the whole map uses: scaling each year on its own made hills move against their BLS numbers. The year slider is one uniform; pins and pointers read the same surface (`surfaceHeight`). Hills blend by smooth max at power 2, not the live sum: on the densest stage the sum inflated the median job 2.09 times. Heights stay float textures unless a real probe fails, when `stageTextures.ts` falls back to 16 bits packed in RGBA8. The world and a stage take turns through `worldStage` and `worldStore.drawnStage`: the world fades out, hills rise; hills flatten, the world fades in. `drawnStage` trails the level, and labels and input follow what is drawn. The treemap (`WorldTerrain`) only ever shows at the world. Textures are disposed on leaving a stage, and rebuilt when the Canvas remounts after a context loss.
- **Labels:** one pure function, `labelsAt` (`utils/labelLevel.ts`), picks the set. At the world it follows zoom through `decideLabels` (threshold `FIELD_LABEL_ZOOM`, a ratio against the whole-world framing, never a raw distance): five family names at the broad view; 22 field names plus job labels once zoomed in. In a family or field the level decides, never the zoom. `world/CameraRig` feeds it every frame, and during a flight it reads the landing's zoom, so a flight home never flashes the field names. A stage's labels stand on the baked surface (`stageMarkerHeights`) and go through the same declutter as the live view. Family labels are real buttons but stay `pointer-events:none`: pointers are hit-tested on the canvas like every other label, keyboards and screen readers use the button. The field picker in `WorldBar` is the keyboard route to all 22 fields.
- **Published numbers:** every score, forecast and label on the role page comes from the bundled `ai_scores.json` (or the user's own opt-in re-score), so every visitor sees the same figures. Live Analyze adds prose only and never overwrites them; `alignAnalysisToTasks` attaches its reasoning to the role's tasks by name, then 40-char prefix, then position.
- **Re-score:** Full map re-score requires the **user’s** Claude API key (not the app default) and shows a token/USD estimate in `RescoreConfirmModal`. Roughly ~50 calls / ~65k tokens / ~$0.50–$0.70 at Sonnet list prices.
- **Modal mounting gotcha:** `Header` uses `pointer-events-none` (with selective `pointer-events-auto` on controls) at `Z.header` (20). Never mount full-screen dialogs inside it — clicks fall through to the WebGL globe/job labels and the year slider (`Z.timeBar` = 110) paints above the dialog. Mount rescore/API modals at `App` root (or portal to `document.body`) with `pointer-events-auto`.
- **3D hover popups:** Job label hover expand is suppressed while `isOrbiting` is true (`OrbitControls` `onStart`/`onEnd` in `Landscape.tsx`).
- **Production:** https://futureofjobs.vercel.app/ auto-deploys from `main`.
- **Agent efficiency:** One agent = one goal (new chat per feature). Keep unused MCP servers off (e.g. Gmail only when emailing). For UI work, use the `ui-polish` skill; do not dump `src/data.ts` or large JSON into context — grep instead. Large dumps are listed in `.cursorignore`.
