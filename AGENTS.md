# Agent notes

## Cursor Cloud specific instructions

- **App:** Vite + React SPA (`npm run dev`). No database/Docker. Claude calls go through `/api/claude/messages`: `api/claude.ts` on Vercel, and the very same handler (`api/_lib/gateway.ts`) under `npm run dev` via `scripts/lib/devApiPlugin.ts`. `FOJ_MOCK_CLAUDE=1 npm run dev` swaps Claude and Supabase for an in-memory mock (`scripts/lib/mockAiBackend.ts`; no key, no real call; `GET /__mock/claude-calls` lists what Claude was asked, `POST /__mock/reset` clears it). Add `FOJ_RATE_PER_HOUR=3` to see the limit message quickly.
- **Package manager:** npm (`legacy-peer-deps=true` in `.npmrc`). Install with `npm install`.
- **Tests:** `npx vitest run` (no `npm test` script). Lint: `npm run lint` (some pre-existing purity/unused-var failures exist outside recent feature work).
- **Claude model caveat:** `claude-sonnet-5` rejects `temperature` — do not send it (see `src/utils/claude.ts`).
- **OOH vintage:** Growth rates are BLS Employment Projections / OOH **2024–2034** (`DATA_SOURCES.BLS_OOH`, `scripts/extract_bls_data.py`).
- **OES vintage — national and state-level extracts are independent and CAN drift apart, so check each one's own source, not this note:**
  - National per-role employment (`src/data.ts`, drives terrain height + the Workers stat + the "OES" badge) is **BLS OEWS May 2025**.
  - State-level employment/LQ (`src/data/geo_real.json`, drives the 2D map) is also **BLS OEWS May 2025** as of the last refresh — but check `geo_real.json`'s own `_meta.bls_release`, don't assume it still matches `DATA_SOURCES.BLS_OES`; the two are refreshed by the same script but at different times.
  - Both are refreshed via `node scripts/refresh_oes_data.mjs`, which pulls `api.bls.gov` directly — `www.bls.gov`/`download.bls.gov` 403 all automated clients, so the classic workbook route can no longer be refreshed programmatically. Requires a free BLS key (`VITE_BLS_API_KEY`; unregistered tier is 25 req/day, nowhere near enough for the ~5,000-series state pass). Rewrites `DATA_SOURCES.BLS_OES` + all 50 `dataSources` literals in `data.ts` together — `src/__tests__/oesVintage.test.ts` guards them staying in sync.
  - `MAP_TITLE_TO_SOC` (`src/utils/onet.ts`) is the single source of truth for both extracts. BLS retired SOC 13-1022/13-1023 (Wholesale & Retail Buyer / Purchasing Agent) and now publishes only the combined broad code **13-1020** — both titles map there as aliases.
- **All-occupations dataset:** `src/data/occupations/` (`index.json` + one `<SOC major>.json` per BLS major group) is built by `python3 scripts/build_occupations.py` from OEWS May 2025, EP 2025–35 Table 1.2 (`data/bls_ep_occupation_2025_35.xlsx`, Wayback capture) and O*NET 30.1; `scripts/verify_occupations.py` re-reads every value from the raw files, including the EP "Summary" rows stored for every continent and minor group. Only `src/utils/occupationIndex.ts` may import it: `index.json` is bundled, continent files load lazily via `import.meta.glob` (`occupations.test.ts` and audit T68 guard both). Display labels live in `src/config/continents.ts`; the BLS title in the data is the official name.
- **22-continent world (phase 2):** the 3D view is `components/world/` (instanced peaks, one draw call per region; region rectangles in the ground shader). In the code, `mapView: 'globe'` is this 3D landscape view, not a globe. Region area = the continent's EP 2025 summary row (`utils/worldLayout.ts`, `continents.test.ts`); position/shape are layout only. `utils/roles.ts` adapts the 50 Kelley jobs + 830 BLS occupations into one list (a Kelley SOC is never listed twice). A BLS occupation opens through `worldStore.selectedOccupationSoc` (never `selectedJob`): a scored one becomes a role-panel Job (`utils/blsRoleJob`, `hooks/useOccupationRole`) and opens the same `JobDetailPanel` as a Kelley role; an unscored one opens the numbers-only `OccupationPanel` and never reaches Claude (`unscoredNoClaude.test.tsx`).
- **Three levels:** the 3D view is at the world, a family or a field, held as `focusedFamily` + `focusedContinent` in `worldStore` (a field's family always comes from `familyOf`). All transitions, what is on stage, the breadcrumb, the Esc and zoom-out rules and every click rule are pure functions in `utils/worldLevel.ts`, so change them there. Any new level state must also be added to Landscape's wake effect, or fades freeze partway (`landscapePause.test.ts`).
- **Stages:** a family or field is its rectangle on the world map, magnified: one map per stage (`stageMapFor` in `utils/stageMap.ts`, a uniform scale plus a translation that puts the rectangle's centre at the origin, fitted to `STAGE_FIT`), so every job, field tile and minor-group block lands where that map sends its world position and nothing changes neighbours between levels. A field more than `FIELD_MAX_ASPECT` (1.2) times as long one way as the other also stretches its short side toward a square, about its centre (20 of the 22 fields; all but Personal Care and Production). There is one layout: `utils/worldLayout.ts` cuts each field into SOC minor-group blocks with the same ordered treemap, sized by job count, jobs on a grid in SOC order inside each; `utils/stageLayout.ts` only applies the map. `CameraRig` lands every stage on `stageFraming` (the live camera, about 32.5 degrees, looking at the rectangle's centre, so orbiting turns about it) and clamps panning to the stage rectangle; it slides the picture with `camera.setViewOffset`, never the camera, so the whole rectangle sits between the top chrome and the year slider: on phones in the middle of the free band (`stageViewOffset`), on desktops only as far as the near edge needs to clear the slider (`stageFitView`; nothing at 1920x958, about 30px at 1280x680, and a little zoom-out of the picture only for windows too short even for that). The hand zoom-out rule is fed through `utils/zoomOutGate.ts`: its threshold is always the level's landing distance x `ZOOM_OUT_RATIO` (zooming in never lowers it, and at a family or field the gate only arms with the camera inside it, so arming alone never fires; at the world, which has no level to leave, the base is `WORLD_BASE` and the gate re-arms on the quiet time alone), and until the camera has been still for `ZOOM_OUT_SETTLE_MS` after a landing, and during a main-button mouse or pen click, wheel-outs are swallowed in the capture phase before OrbitControls sees them (zoom-in always goes through; touch pinch is never held off). So a click never changes level except through `clickAction`, a brush never leaves the camera zoomed out, and one coasting scroll climbs one level, not two. Reset view hides on phones inside a family or field (`utils/resetView.ts`). **Flights are zooms:** `world/worldView.ts` holds one map from the world's ground to the screen's, which `CameraRig` (mounted first) blends each frame on the camera's own clock (`utils/stageTransition.ts`, pure and tested); the treemap (`WorldTerrain`, through a `uView` uniform), the stage surfaces, pins and labels all draw through it, so the block being opened magnifies in place. Going in, the inner layer fades in on top early at heights matched to the layer under it (`heightRef`), grows to its own scale, and everything else fades; going out runs backwards; a flight interrupted part way carries on from what is on screen. Never pass the live `worldView` as a transition's start without copying it. `world/StageTerrain` draws one mesh per stage on screen (two during a hand-over): the live Terrain.tsx shader in `world/stageShaders.ts` on the stage's own rectangle, displaced from baked textures, with the world map's tile borders and outline and a straight edge (no circular fade); `utils/stageBake.ts` bakes over that rectangle with square texels, each hill's width from its world footprint, heights tapered to the ground across the empty inset band so the edge is clean and no job's own height changes. Two height layers (2025 and 2035) on one fixed scale per stage, `stageMaxEmployment`: scaling each year on its own made hills move against their BLS numbers. Hills blend by smooth max at power 2, not the live sum. Heights stay float textures unless a real probe fails, when `stageTextures.ts` falls back to 16 bits packed in RGBA8. `worldStore.drawnStage` is the stage whose layer is fully drawn; labels and input follow it. A family offers only its fields: no job labels, pins or job clicks, even with the Kelley filter on, which just dims its hills; job roles start inside a field. Textures are disposed when a layer fades out, and rebuilt when the Canvas remounts after a context loss.
- **Labels:** one pure function, `labelsAt` (`utils/labelLevel.ts`), picks the set. At the world it follows zoom through `decideLabels` (threshold `FIELD_LABEL_ZOOM`, a ratio against the whole-world framing, never a raw distance): five family names at the broad view; 22 field names plus job labels once zoomed in. In a family or field the level decides, never the zoom. `world/CameraRig` feeds it every frame, and during a flight it reads the landing's zoom, so a flight home never flashes the field names. Every label keeps its world map position at every level and is drawn through the view's map. A stage's labels stand on the baked surface (`stageMarkerHeights`) and go through the same declutter as the live view; a family's field names sit on their tiles, and a field's minor-group names come last and show only on their own block where the job labels leave room. Family labels are real buttons but stay `pointer-events:none`: pointers are hit-tested on the canvas like every other label, keyboards and screen readers use the button. The field picker in `WorldBar` is the keyboard route to all 22 fields.
- **Published numbers:** every score, forecast and label on the role page comes from the bundled `ai_scores.json` (or the user's own opt-in re-score), so every visitor sees the same figures. Live Analyze adds prose only and never overwrites them; `alignAnalysisToTasks` attaches its reasoning to the role's tasks by name, then 40-char prefix, then position.
- **Business & Finance scores:** the 13 SOC-13 occupations no Kelley title covers get published scores in `src/data/ai_scores_bls.json`, written only by `npm run generate-bls-scores -- --proxy https://futureofjobs.vercel.app/api/claude/messages` (same model/prompt/parser as `ai_scores.json` via `scripts/lib/claudeScoring.ts`; tasks fixed in `data/bls_scoring_plan.json`; a 5-role control run must pass first; every call is logged in the gitignored `data/ai_scores_bls_run.json`; `--max-calls N` per run, default 30, never above 450). The app never imports the file itself: the Vite plugin `scripts/lib/blsScoresPlugin.ts` serves `virtual:bls-scores` (meta plus one Automation Risk per SOC, in the main bundle) and one slimmed chunk per field, which `worldStore.loadContinent` loads with the field's occupation file (`loadBlsFieldScores`), so `blsScoreFor` is only filled once a field is loaded; the parse and slimming rules are in `utils/blsScoresData.ts` and `blsScoresSlim.test.ts` checks the chunks against the full file. With no file, nothing is scored. These roles stay `kind: 'bls'` (not in the store's jobs list or the Kelley toggle) but are otherwise one app with the Kelley roles: see **One common app** below. `ai_scores.json` is hash-pinned in `blsScores.test.tsx`. `oohEnvelopeCap` lives in `utils/oohEnvelope.ts` so the Node generators can load `taskScoring.ts` (terrainMath pulls in Vite-only `import.meta.glob`). **The other 770:** `--plan` also writes `data/bls_score_plan_all.json` (every unscored SOC, sorted by scoring family 1 Management/Business/Science/Arts, 2 Sales and Office, 3 the rest; task rule own code / sub-codes / combined / no tasks; promptSha256), and `--family 1|2|3` or `--fields 11,15` scores one batch, through `--proxy` or `--direct` (key `FOJ_SCORING_API_KEY` or `~/.foj_scoring_key`, workspace `FOJ_SCORING_WORKSPACE` or `~/.foj_scoring_workspace`, never `ANTHROPIC_API_KEY`; same body byte for byte). Decisions (combine rule, the 47 unscored "All Other" jobs, ranks) are in `docs/scoring-decisions.md`. Coverage text everywhere comes from `SCORE_COUNTS` / `SCORE_COVERAGE` in `utils/blsScores.ts`; `public/student-guide.html` copies `components/Modals/studentGuideFeatures.ts` word for word (`studentGuide.test.ts`), and its PDF is printed with headless Chrome (fonts in `public/fonts/`).
- **One common app (2026-11-08):** every scored role, Kelley or not, opens `JobDetailPanel` with the same features (Analyze / Strategic Insight, Roadmap, Scenario, Defend / Build, Save role, Human Resilience, task view). Kelley-only facts are small labels on Kelley roles (`data-testid="kelley-label"`, the pay line's "Shares BLS code with…"). A role id is the Kelley job id (`job-15`) or `soc:<SOC>`; saved roles, views, upskill and dashboard all take both (`utils/blsRoleJob` `blsSummaryJob` for dashboard rows). **Ranks:** one scale across all scored roles (`utils/roleScale`, `utils/allRoleScale`): Human Resilience quartiles, volatility, colour-band terciles and every "rank" text use every scored role once (each Kelley title, each other scored occupation; the three shared BLS codes are not counted again), so `SCORE_COUNTS.roles` = 786 roles from 783 occupations. The main bundle carries one risk and one human mean per BLS SOC (`virtual:bls-scores` `risks` + `humans`) so ranks need no field load. `scripts/rank_table.ts` writes the 50 Kelley roles' before/after table (`fixtures/kelley50_rank_change.json`, checked by `rankScale.test.ts`). **State map:** Kelley roles only, by data: `geo_real.json` (OEWS May 2025) covers their 47 SOCs; the repo's only all-occupation state file is `data/all_data_M_2023.xlsx` (May 2023), not mixed in. **No OOH badge** on non-Kelley roles (no OOH extract for them).
- **Claude gateway + shared answers (2026-11-08):** the browser never sends a prompt on the server key. It sends `{ feature, input }`; `api/_lib/gateway.ts` checks it against `src/shared/aiFeatures.ts` (feature table: zod input schema with size caps, model `claude-sonnet-5`, max_tokens, output check) and builds the prompt itself (`src/shared/aiPrompts.ts`, moved word for word from `utils/analysis.ts`). Role features (`analyze`, `scenario`, `roadmap`, `upskill`) are **shared**: the first answer that passes the check is saved in Supabase `ai_shared_answers` (migration `0003_shared_ai_answers.sql`, server-only, RLS on, no policies), keyed by role + feature + prompt version + SHA-256 of the exact request; every later visitor gets it with no Claude call. Résumé features (`skills`, `startup_core`, `startup_plans`) are never saved. A raw Anthropic body is forwarded only with the visitor's own key and `x-foj-feature: rescore|ping` (re-score, System status), shape-checked. **Rate limit:** only a NEW answer on the server key counts: per visitor (SHA-256 of IP) 30/hour and 100/day, whole app 1000/day (`FOJ_RATE_PER_HOUR`, `FOJ_RATE_PER_DAY`, `FOJ_RATE_GLOBAL_PER_DAY`), counted atomically in Supabase (`ai_rate_take`), falling back to per-instance memory. Server env: `ANTHROPIC_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_URL` (or `VITE_SUPABASE_URL`); `GET /api/claude/messages` reports which are missing (names only) and System status shows it. Delete one saved answer: `node scripts/shared_answers.mjs delete --role soc:29-1141 --feature roadmap --yes`. Files under `api/` and `src/shared/` reached by the function import relative paths with `.js` (Node ESM on Vercel; `aiGateway.test.ts` guards it). `generate-*-scores --proxy` on the server key is now refused: use `--direct`.
- **Re-score:** Full map re-score requires the **user’s** Claude API key (not the app default) and shows a token/USD estimate in `RescoreConfirmModal`. Roughly ~50 calls / ~65k tokens / ~$0.50–$0.70 at Sonnet list prices.
- **Modal mounting gotcha:** `Header` uses `pointer-events-none` (with selective `pointer-events-auto` on controls) at `Z.header` (20). Never mount full-screen dialogs inside it — clicks fall through to the WebGL globe/job labels and the year slider (`Z.timeBar` = 110) paints above the dialog. Mount rescore/API modals at `App` root (or portal to `document.body`) with `pointer-events-auto`.
- **3D hover popups:** Job label hover expand is suppressed while `isOrbiting` is true (`OrbitControls` `onStart`/`onEnd` in `Landscape.tsx`).
- **Production:** https://futureofjobs.vercel.app/ auto-deploys from `main`.
- **Agent efficiency:** One agent = one goal (new chat per feature). Keep unused MCP servers off (e.g. Gmail only when emailing). For UI work, use the `ui-polish` skill; do not dump `src/data.ts` or large JSON into context — grep instead. Large dumps are listed in `.cursorignore`.
